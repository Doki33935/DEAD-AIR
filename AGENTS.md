# Работа с DEAD AIR

Перед изменениями прочитай docs/PROJECT_CONTEXT.md, затем нужные документы из README.md. Проверь структуру и git status. Пиши команде на русском.

## Текущее задание и границы

Этап — планирование. По текущему запросу разрешены только Markdown-документы, очистка устаревших планов и публикация в dev. Не создавать UE-проект, код, ассеты, плагины или конфиги без следующего задания на реализацию.

Сценарий утверждён Doki. Не открывать заново биографию, тексты кассет, лор горы/Отклика и две концовки. Отличать решения тимлида от рабочих рекомендаций и результатов проверки. Новые существенные творческие изменения согласовывать; мелкие параметры реализации решать в пределах задания.

## Зафиксировано

- UE **5.0.3**; одна комната, мышь для всего пути от меню до перезапуска.

- Демо 20–30 минут; два сюжетных отдыха без бодрости. Поиск T2 останавливает сюжетные часы.

- Слава — UE; Ярик — 3D; Прохор — 2D/UI; Doki — сценарий, данные, интеграция и сдача.

- Звукач внешний, делает весь звук; конкурсная допустимость ещё не подтверждена.

- Голоса и актёрские указания — docs/AUDIO_SCENARIO.md. Порядок сцен — docs/SCENARIO.md. Не держать параллельные версии канона.

- Прямой запрос даёт проверку; делегирование — сохраняемые 50/50; местный журнал — плохой финал. Поздний прямой запрос возможен до закрытия отчёта.

- Готовность 29 ноября 2026; GDD 21 ноября, арт/программирование 28 ноября, продукт 1 декабря.

## Как работать

Сначала цель, зависимости и критерий результата; затем небольшие шаги по владельцам. Не раздувать объём. Задачи и риски находятся в docs/TEAM_TASKS.md, без оценок личной занятости участников.

При следующем задании на реализацию начать с Blueprints, UMG, Audio Components/Sound Cues и Data Tables. Новые сигналы существующего типа добавляются через данные. Проверять неверные параметры, повтор действий, загрузку и прохождение мышью.

Не утверждать, что UE, Windows-сборка, звук или ассеты проверены, если проверки не было. Новые API и редакторские инструкции сверять с 5.0.3.

Не покупать ассеты. Правила, источники и внешнее авторство сверять по docs/SUBMISSION_CHECKLIST.md и официальным материалам; не подменять требование предположением. Учитывать 12+ во всех материалах.

Не перезаписывать чужие изменения, не добавлять секреты/сборки/кэши. Один владелец бинарного ассета в момент редактирования. Git LFS и .gitignore настраивать на этапе создания проекта.

Не делать reset --hard, force push или массовое удаление без явного запроса. Текущая очистка устаревших Markdown и push в dev разрешены пользователем. Перед удалением проверить состав файлов и сохранность актуального содержания.

По завершении сообщать результат, проверки и оставшиеся ограничения. Актуализировать существующие восемь документов, не плодить архивы v02/v03 и повторяющиеся списки решений.
