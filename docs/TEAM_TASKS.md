# DEAD AIR — актуальное ТЗ и задачи команды

**20.11.2026. UE 5.0.3, Windows, одна комната, мышь.** Сценарий утверждён. Владелец бинарного ассета в каждый момент один; не менять чужую раскладку UI и не расширять сюжет/набор приборов.

## Текущая база

В dev реализованы комната, меню/учебные сохранения, радио/дека, вставка/снятие и катушки. Взаимодействие вынесено в BP_OperatorController + BPI_Instrument; BP_DeskWorkstationRig теперь только камера. Рабочие кнопки/звук принадлежат прибору. Камеры приближения прикреплены к приборам. Стол можно ретекстурировать без переписывания механик. Исторические задания «создать проект/первое радио» закрыты и не являются новой работой Славы.

Расстановка: оба прибора ближе к обзору, реквизит освобождает фронтальную зону; локальный тёплый свет 2900 K, центральная тусклая лампа 3300 K / 1,25 cd. Системный блок убран, компьютерное крыло столешницы расширено до 100 × 119 см; предметы опираются на поверхность, кассета лежит внутри отсека под прозрачной крышкой. Курсор скрыт в обзоре, виден в меню/приближении, ПКМ назад. Верхние переходы/крестик/учебная панель отсутствуют. Поворот к кровати — удержание у правого края, обратно — у левого. Вход в паузу через кровать пока не подключён.

Полный сюжет, REC/таймер, терминал, квитанции, сюжетные сохранения и финалы ещё не готовы. Текущая сборка — работающая техническая основа; не описывать её как завершённые 20–30 минут.

## Слава — ближайшая работа UE

Цель — пройти мышью от меню к первой подтверждённой рабочей квитанции, сохранив готовые приборы. Зависимости: текущая dev/LFS, данные Doki, UI Прохора. Критерий результата — правильный ответ подтверждён квитанцией; ошибка объяснима и допускает повтор, состояние восстанавливается.

1. Получить dev и git lfs pull, открыть MainMenuMap. Прочитать карту ответственности/контракт в [UE5_ARCHITECTURE](UE5_ARCHITECTURE.md). Сначала Blueprint контроллера, затем BPI у приборов и камера; общий ввод не возвращать в радио/стол.
2. Пройти обзор/кровать/оба прибора вручную. ЛКМ приближает только выбранный прибор, ПКМ возвращает; нет клика сквозь меню, повторного zoom во время blend и потери курсора. Проверить два разрешения и край viewport.
3. Проверить ручки кругом 1:1, OFF/ON/нулевую громкость, уход с канала и продолжение, фильтр до/после сигнала, разные оптимумы. Луч по видимой кнопке питания должен попадать именно в неё.
4. Дека: кассета целиком в приближении, повторный клик не прерывает движение; PLAY/FF/REW/STOP/конец ленты; отдельные фазы, неподвижный корпус. Загрузка во время переноса/перемотки, одновременный звук с радио и субтитры, возврат из меню без обнуления позиции.
5. Подключить существующий OpenPause через кровать; не возвращать верхнюю кнопку МЕНЮ или клавиатурный обход. Не менять условия двух сюжетных отдыхов.
6. Подключить первую цепочку из MECHANICS: станция 153450 кГц → прослушивание 27 → ввод в журнал/отчёт → отправка → квитанция. Поля/события в данных, не в UMG. Проверить неверные частоту/ответ, повтор вызова/отправки, двойной клик, сохранение/загрузку.
7. Снять реальный Game Loop и User Flow для GDD; честно отделить рабочее от запланированного. Передать Doki commit, сборку и результаты ручного прохода.

## Ярик — модели и текстуры

На рабочем столе подготовлена **DEAD_AIR_3D_ARTIST**:48 игровых моделей/деталей,2 справочных примитива UE,72 PNG, FBX всей расстановки, Models.csv/manifest.json и README_ХУДОЖНИКУ. Для стола использовать обновлённый Updates/DeskFit/Table_Wider.fbx; рядом новая Reference_Room.fbx. Исходная папка Models/Textures не перезаписывается. Начать с радио/деки, затем стол/реквизит. Сохранять UV0/pivots/порядок material slots. Кнопки и ручки не объединять с корпусом; ступицы кассеты связаны с материалом, их UV не сдвигать без интеграции.

Возвращать отдельные BaseColor/Normal/Roughness/Metallic/AO либо согласованную ORM. Указать DirectX/OpenGL normal; рабочий ориентир 2 K для приборов,1 K для мелочей. Модели/текстуры передавать отдельно от игрового Content; UE-интеграция делает замену и проверяет свет/хитбоксы.

Исправить исходник Тарелка(NEW)4:7 оболочек с обратным обходом, один открытый контур; рабочая копия уже без точных дублей. Камеры/свет изDCC не включать в mesh-экспорт. Для финального поворота нужны согласованная ось/отдельные детали; сам финал ещё не интегрирован.

Передать Doki ссылки/авторов/лицензии бесплатного реквизита комнаты. Названия Fab/Megascans/FreeFurniturePack/SurvivalProps и т.п. не заменяют источник. Экспорт моделей не передаёт авторство команде.

## Прохор — UI и внешний вид

Принять читаемость радио/деки при тёплом локальном свете и тусклой центральной лампе; финальные текстуры не должны делать все поверхности одинаково яркими. Подготовить макет экрана с учётом существующих размеров окон, IBM Plex Mono Medium/SemiBold; ручные положения Doki сохраняются. Не запекать динамическую осциллограмму/цифры на корпус.

Для внешнего фона вместе с Яриком сделать сначала черновик через игровое окно:3D-ближний план/тарелка, простая главная гора, рисованные дальние слои/небо, отдельный туман — это рабочая рекомендация из MECHANICS, окончательный выбор за Doki. Проверить все ракурсы до подробной отрисовки. Не менять сценарные состояния погоды/тарелки.

## Правила передачи и риски

Нормальный commit/push в dev, без force/reset. Новые бинарные ассеты через LFS, кэши/сборки/настройки не коммитить. Один владелец бинарного ассета. Автоматические проверки показывают конкретные функции, не заменяют прохождение внешним игроком. Главные оставшиеся риски: неполный сюжетный маршрут/REC/SaveGame, отсутствие игрового входа в паузу, лицензии реквизита/внешний звук, финальные VO/фон и проверка сборки на другом ПК.

При передаче фиксировать фактический commit, какие действия проверены, что ещё не проверено и кто принимает. Не оценивать личную занятость участников и не расширять объём перед сдачей.
